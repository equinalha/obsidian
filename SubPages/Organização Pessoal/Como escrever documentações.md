1. Use termos de forma consistente

É melhor repetir-se e ter a documentação o mais clara possível do que tentar não repetir palavras.

Exemplo: “kubernetes é uma plataforma…. e o k8s".
O melhor aqui é repetir a palavra kubernetes.

"Isto" se refere ao que? O ideal é substituir pelo substantivo desejado.

2. Repita os substantivos

Quando usamos pronomes no lugar de substantivos vamos ter frases ambíguas.

Exemplo: "Clojure é uma linguagem funcional, enquanto Java é orientado a objetos. Isto é…”

"Isto" se refere ao que? O ideal é substituir pelo substantivo desejado.

3. Prefira voz ativa a voz passiva

Durante a leitura convertemos voz passiva para ativa. Então por que adicionar esse processamento extra?

Além disso, voz passiva reporta ações de forma indireta e muitas vezes esconde o sujeito da frase.

4. Continuação

Mais um ponto a favor, é que normalmente voz ativa é mais curta do que passiva.

Exemplo:

"Testes são implementados pelo codebase" (voz passiva) →
“O codebase implementa testes” (voz ativa)

5. Use verbos fortes

Devemos engajar nossos leitores, e para isso precisamos evitar verbos fracos como "acontece", "ocorre".

Algumas das substituições possíveis são: "acionam", "geram", "garantem”.

6. Evite termos inconclusivos

"extremamente rápido”. O que é rápido? 5 segundos, 10 milissegundos?

Substitua por informações numéricas.
Exemplo:
"o request demora 1 segundo"

7. Cada frase deve ter somente uma ideia

Se você tiver frases muito longas, irá perder o leitor no meio da linha de raciocínio.

Uma das soluções para frases longas é convertê-las para listas. Se você tiver um "ou", transforme em uma lista.

8. Seja conciso

Remova palavras desnecessárias da documentação.
"nesse momento" → "agora”
"determinar o local de" → "encontrar”

9. Responda "o que", "por que", "como”

"O que você está tentando transmitir?”

"Por que é importante para o leitor saber disso?”

"Como o leitor deveria usar esse conhecimento?”
